# 融合 Skill 的完整运行层

这不是“Director 加几条补丁”。Director 原能力、用户已确认的编导判断和 Remotion 执行共同构成一个系统。不要把任一层降级成可有可无的附录。

| 层 | 固定保护什么 | 每个项目如何判断 | 留下什么记录 |
| --- | --- | --- | --- |
| 1. Director 原能力 | Vendor、主题预设、风格多轴、Beat/Shot、关键帧、A/B/C-roll、元素动画、本地运动机制 | 按语义选择可调用能力，不修改 Vendor | 来源与调用能力 |
| 2. 原片与原声 | 原声、口型、动作、文案语义、人设 | 原声为时间主轴；不重新配音 | 原片、SRT、文本路径 |
| 3. 原始资料拆解与审核 | 素材指纹、创作者身份、原文、主张来源、时间段、参考范围和禁止虚构 | 公开链接可调用拆解 Skill；本地私有资料本地处理；用户批准后才通过闸门 | `source-review.md` + `source-audit.json` |
| 4. 内容/语义记录 | 受众、传播目的、主张、钩子、信息推进、呼吸 | 一句话不必一镜；由语义变化切分 | 语义单元与观众结果 |
| 5. 语义简报 | 一段一个观众理解任务 | 我们只交代要看懂的关系、参考范围、禁令和原声语境；不替 Director 规定隐喻、中心、画面载体或组件 | Director brief |
| 6. Director 视觉决策 | 视觉 DNA、主题、组件、构图、信息层级、完成度 | Director 按媒介、时代、构图、色彩、字体、印刷、情绪、运动多轴提出多样画面方案；锚点锁语法，不锁颜色、版式、组件或画风 | theme / component / composition proposal |
| 7. 人设/真人 | 真人为记忆点，不是每帧主角 | 我们给出原片、可用动态形式、脸部禁令和人设目的；Director 按构图提出全屏、动态抠像、圆/方/矩形动态窗口或不出现 | persona proposal + approval |
| 8. 素材与组件 | 组件为解释服务，不是装饰 | Director 主导地图、照片、卡片、列表、Dashboard、纸媒、受控3D、MJ/MG等组件选择；多人与多角色必须是真实不同素材 | component proposal + source |
| 9. MG 动画 | MG 是生命力增强层，不是第二主风格 | 复杂关系才写 MG 任务单；进入→构建→结论→停留→接力，缩放只可辅助 | 图层、关系、节奏、转场 |
| 10. 平台与画幅 | 三级安全区、字幕可读、横竖版重构 | 一级信息/脸不遮挡；次级信息读完可轻遮；装饰可进平台区；横竖版重构而非机械裁切 | 平台与保护分级 |
| 11. 关键帧审批 | 先审画面再审动画 | 候选数量由不确定性决定；关键帧必须来自实际 Remotion 合成 | 帧 ID、批准/否决原因 |
| 12. 执行与声音 | 本地 Remotion、原声连续、默认低调 BGM | 默认启用本地纯器乐；用户明确退出时才关闭；付费音乐生成仍需成本确认 | 工程路径、输出路径、音乐决定 |
| 13. 验收、返工与版本 | 已批准内容不被误伤 | 抽帧检查语义、脸、安全区、MG、呼吸和成片质量；只返工失败段 | QC 结果、preserve/remove/rebuild/recheck |

## 不要误用层级

- 不用一种批准画面统治全片；先标注它是 `scene_solution`、`visual_quality`、`technical_mechanism` 还是明确的 `system_anchor`。
- 不用一个全球默认画风覆盖 Director 的多主题能力。
- 不用“真人应出现”替代“真人在此段是否有语义/人设价值”；也不由外层预先指定真人形式。
- 不用“所有元素拆层”替代“每段都必须复杂 MG”。
- 不把 Video Spec 设为核心必经门槛；项目复杂时可写内容大纲，简单项目可直接进入语义记录。

## 关键帧交付规则

审批帧是 Remotion Composition 的实际截帧。若构图计划中有真人，帧中必须呈现该动态视频/动态抠像容器的实际位置与脸部净空；孤立海报、生图或素材拼板不能代替审批帧。
