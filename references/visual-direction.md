# 视觉编导与镜头制作

内容理解保留已确认原话、语义顺序及前后依赖。视觉编导把这些内容转成具体画面，不补写原文没有的冲突、观点或故事。

## 顺序

理解原文与用户意图 → 内部拟定视觉方向 → 查阅所选 Director / video-shotcraft 的资产与实现依据 → 完善具体大纲并执行交付前自审 → 交付一份完整稿子 → 按用户授权进入资产生产和 Remotion 实现 → 实际关键帧与动态预览审核。

同一份稿子先简要说明方向、选择理由和主要取舍，再展开画面、动作、衔接、音效、实现依据及待验证项。大方向是大纲的摘要，默认不单独设一轮确认；用户明确只要方向时除外。只有会改变整体结果且不能从上下文判断的关键歧义，才先询问。固定的是工作顺序和交付完整性，不固定镜头数、创意、版式或风格；不要先交含糊概念，等用户否定才补设计。用户授权常规编导判断时由代理完成，不反复要求用户替代理选优或补检查。

核对能力只是查阅相关配方、代码和资产条件，不提前生成成片。不要每个项目全量读取两个库。

## 两个视觉来源

- Director 提供视觉语言、材质、摄影/拼贴、物件构图和生成资产方向。
- video-shotcraft（镜头制作）提供镜头配方、产品模板、卡片版式、运镜和声画配合。整套模板、局部镜头和单独运动机制均可使用，选择必须在本次执行大纲中说明。
- 默认不继承上一项目模板。不得把镜头库的产品配色、固定停留时长、BGM 节拍或个人偏好自动套到原声口播上。

## 每镜从抽象要求落到具体执行

执行大纲需包含：原话及含义、实际物件/图片、素材来源、独立图层与遮挡关系、起始/落定构图、元素轨迹、相机运动、进入/落定/阅读/退出时间、文字时机、音效落点、承接下一镜的元素。

例如“多个渠道的信息汇到一起”：明确每个渠道的物件、错峰入场与汇聚路径，相机何时拉开、关键词何时出现、汇聚声落在哪里、中心物件如何进入下一镜。不能只写“汇聚动画”。这些都表达原话已有关系。

大纲确认前逐镜核对：图层是否真能独立控制；图片是否仍需生成；选用镜头是否有对应实现；帧数是否足够；资产缺失时如何返回设计。不得制作时静默降级为整图缩放。

## 交付前自审

内容提纲用于内部组织，不等于可执行视觉方案。请求用户审核前，编导先完成以下检查，并将结论写进当前 `edit-outline.md`；不得用“第二版更好”等口头评价代替修订文件。

- **具体动作**：每个关键节点关联原话、具体物件、起始与落定构图、动作过程、遮挡或接触关系、承接下一镜的元素。只有“出现阻碍、路径推进、抓住机会”等抽象词时继续设计，不交付为完成方案。
- **实现证据**：所选 Director 资产路线或镜头配方必须实际查阅，记录准确资源路径及该资源支持的动作。复用镜头库时核对所选卡和对应代码，不用库名代替证据。自行实现的镜头写明自制方案、可控图层和待验证点，不伪造配方引用。只加载选中路线；不要求全量预读库。
- **声画事件**：对需要音效的关键动作写清触发原话、动作事件（如接触或落定）、声音类型、相对人声强弱、持续时间或范围。没有必要的节点明确不加音效并写理由；不强制每个关键词配声。时间码未校准时标为待对齐，不编造精确帧。
- **编导判断**：逐镜回答观众新看懂了什么、为何用这个物件、与上一镜怎样连续。若换成任意励志文案仍可原样套用，需加强与当前原话的对应；仅减少镜头数、增加图层或补音效不算解决视觉表达问题。
- **状态真实**：区分已核对实现、待生产资产、待动态验证。资产未生成可以提交明确的生产计划，但实现路线未核对不能称为可执行大纲；自审不能宣称实际声画质量已通过。

用户已授权继续时，常规编导选择由代理完成。交付审核用于确认表达方向或真实效果，不让用户替代理寻找缺失字段、选择明显更完整的方案。若现有方案未通过自审，先改文件并报告具体改动；用户要求先修流程时，暂停下游测试，完成所需局部技能修复后再继续，不循环道歉、解释或索要同一确认。

## 可分发接入（资源定位）

video-shotcraft 已内置在 `vendor/video-shotcraft/`，来源、固定版本和分发范围见 [内置库接入说明](shotcraft-integration.md)。不依赖用户另装同名 Skill，不从本机其他目录偷偷借用文件。保留上游技能、镜头卡、模板、组件和代码的目录关系；不把原技能拆成散落的规则。

按内置库 gallery/api/library.json 定位选定镜头，再读取该配方及准确 demo 源码；仅加载选中的内容。复用代码/资产时保留各自许可与署名文件。具体画面质量须用动态预览验证，安装成功不等于效果合格。
